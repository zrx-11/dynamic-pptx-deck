# 页级局部重生成工序指南

> 本文件规定成稿交付后，当问题只局限在单页时，如何只重建该页并回填整包，而不
> 触动其余页面。回填工具为 `scripts/page_regen.py`，在包级 zip 操作上完成单页
> 替换、资源复制与 rId 重映射；结构化源契约见 `deck-manifest.json` 口径（同目录
> 契约：`pages[].index / page_type / content / assets / notes`、`facts`、
> `assets[]`）。跨包整页导入的适配前置口径见 `import-guide.md`；动画与配对纪律
> 见 `animation-orchestration.md`。

## 1. 适用范围与边界

- **只替换一页**：回填后总页数、页序不变；除目标页外，其余 slide 部件的 XML
  字节与替换前逐字节一致（回填报告 `unchanged_others` 为真，可再用 sha256
  逐页复核）。
- **资源按需复制**：被替换页引用的图片、媒体、图表、嵌入对象等内部资源按传递
  闭包复制进目标包并完成 rId 重映射（图表携带其嵌套的嵌入数据表等部件）；与目标
  包已有部件同名且字节一致时直接复用，命名冲突自动加后缀。版式关系改挂目标稿
  原有版式；母版、主题、备注页由目标稿侧保留，不随来源包搬运；内部超链接关系
  判校验失败，外部超链接原样保留。
- **不做的事**：不增删页面、不调整页序、不重排跨页 Morph 配对、不修改全局母版
  / 版式 / 主题；这些属于整稿重跑范畴（见第 2 节）。

## 2. 单页重生成与整稿重跑的判定条件

### 2.1 只需重生成一页

同时满足下列条件时，走页级回填：

1. 问题限定在单页：该页的文案、数据、表格、图表或装饰层需要调整，其余页面的
   结构、层级与时序不受影响。
2. 不跨页改动：不新增或删除页面，不改变页序，不改动跨页配对对象的命名、归属
   或出场顺序。
3. 结构化源可独立修订：`deck-manifest.json` 中该 `index` 对应的 `content` 与
   `assets` 条目可单独更新；`facts` 中的内容归属不涉及其他页。
4. 全局资产未变：母版、版式、主题色、字体阶梯、全局背景配方保持原样。

### 2.2 必须整稿重跑

出现下列任一情形，停止页级回填，回到整稿构建路线：

1. 页序变化、页面增删，或跨页 Morph 配对需要重新编排。
2. 全局主题、配色、版式、母版或字体阶梯变更，影响多页渲染。
3. 多页共享的装饰资产、背景配方或媒体资源需要更换。
4. 容器—文字配对、跨页配对在多页上失效，单页回填无法恢复成对关系。
5. `facts` 或多页 `content` 的归属需要联动修订，结构化源不再是单页级改动。

## 3. 工序总览

1. 备份原包，作为回滚基线（第 9 节）。
2. 从 `deck-manifest.json` 定位目标页及其结构化源引用（第 4 节）。
3. 只重建该页，产出独立单页包（第 5 节）。
4. 用 `--check-only` 做可行性预检，再回填到整包副本（第 6 节）。
5. 对整包复跑结构检查与配对检查（第 7 节）。
6. 登记重生成清单：页号、页型、结构化源引用、替换前后哈希、复制部件与检查结果
   （第 8 节）。

## 4. 定位目标页（结构化源）

1. 在成稿同级目录读取 `deck-manifest.json`。
2. 按演示顺序（1 基）取 `pages[]` 中 `index` 等于目标页码的条目：
   - `page_type`：页型，用于核对重建页的角色与骨架；
   - `content`：该页结构化文案清单，重建后逐槽位核对；
   - `assets`：该页引用的图片填充等资源路径；
   - `notes`：装饰层处置备注。
3. 沿 `assets[]` 登记项核对资源：路径、生成器、参数与已登记哈希；若重建页改用
   新资源，先在 `assets[]` 补登记，再回填。
4. 齐全性对照契约：条目缺失判 `SOURCE_MISSING`；`content` 为空或图片填充引用
   未登记资源判 `SOURCE_INCOMPLETE`。结构化源不齐时先补源，不直接回填。

## 5. 重建单页包

1. 只产出一张幻灯片：可走整页导入路线（`scripts/slide_importer.py`，参考件
   适配检查通过后导入），也可走原生构建路线（`scripts/dynamic_deck.py` 封装
   函数只画该页）；两条路线的分工边界见 `import-guide.md` 第 1、9 节。
2. 单页包内只允许出现一张幻灯片；该页的关系只挂接自身实际使用的资源，不携带
   无关页面、备注页或多余媒体。
3. 重建页的文本优先保持 `a:t` 节点；装饰层图像化按三档分层原则处置，结构层
   （页序、页型、内容归属）不允许图像化。
4. 单页包保存为独立文件，不覆盖成稿原包。

## 6. 预检与回填

### 6.1 可行性预检

```
python3 scripts/page_regen.py --deck DECK.pptx --page N \
    --from NEW.pptx [--from-page M] --check-only
```

预检只校验可行性，不写出包文件：页码是否在目标稿范围内、来源包是否含足够页码、
关系是否可解析、资源部件是否存在、是否存在不支持的关系类型。预检通过再进入回填。

### 6.2 回填

```
python3 scripts/page_regen.py --deck DECK.pptx --page N \
    --from NEW.pptx [--from-page M] --out OUT.pptx \
    [--report-json OUT.json]
```

- 页码均为 1 基、按演示顺序；`--from-page` 缺省取来源包第 1 页。
- 工具只写 `--out` 指定的输出包，不修改 `--deck` 原包。
- 回填后自动复核：总页数不变、除目标页外其余 slide XML 哈希与回填前一致；任一
  项不满足判校验失败，不产出可用包。

## 7. 整包复跑检查

回填完成后，对输出整包依次复跑下列两个检查（不是只查目标页）：

1. 结构与动画编排检查：

   ```
   python3 scripts/dynamic_deck.py check OUT.pptx
   ```

   退出码：0 全部通过；1 存在问题；2 用法或包不可读。

2. 容器—文字配对检查：

   ```
   python3 scripts/pairing_check.py OUT.pptx
   ```

   可选参数：`--min-gap`、`--max-gap`、`--max-ctn`、`--json OUT`、`--md OUT`。
   退出码：0 全部 PASS；1 存在 FAIL；2 读取错误。

两项检查退出码均为 0，整包才算通过；任一为 1，按第 9 节回滚并回到对应工序
排查。跨页配对计数与孤儿文字以配对检查报告为准。

## 8. 重生成清单登记

每一页级回填都要留一条记录，字段如下：

| 字段 | 含义 |
|---|---|
| `index` | 目标页码（1 基，按演示顺序） |
| `page_type` | manifest 登记的页型 |
| `source_ref` | 结构化源引用：manifest 条目位置、`facts` 小节、`assets[]` 路径 |
| `hash_before` | 回填前目标页 slide XML 的 sha256 |
| `hash_after` | 回填后目标页 slide XML 的 sha256 |
| `copied_parts` | 本次复制进整包的资源部件清单（与回填报告一致） |
| `checks` | `dynamic_deck.py check` 与 `pairing_check.py` 的退出码 |
| `unchanged_others` | 其余页 XML 是否逐字节一致（回填报告字段） |

清单可落成 JSON，与成稿同级存放；`hash_before` 取自回填前对整包的逐页哈希快照，
`hash_after` 取自回填后的输出包。其余页的哈希应与快照逐一相等。

## 9. 失败回滚

1. **回填前备份**：先复制原包为备份副本（独立文件，不与输出包同名），记录备份
   包的 sha256。
2. **失败处置**：预检失败、回填校验失败、或两项复跑检查出现非 0 退出码时，丢弃
   本次输出包，不覆盖原包；需要重试时从备份副本重新出发。
3. **恢复**：若输出包已混入交付目录，用备份副本替换；恢复后复核页数与其余页
   哈希，确认整包回到回填前状态。
4. 原包在任何环节都不应被就地改写：回填、预检、检查均读取原包或其副本，写入只
   发生在 `--out` 路径上。

## 10. 接口与报告字段

### 10.1 CLI

```
python3 scripts/page_regen.py --deck DECK.pptx --page N \
    --from NEW.pptx [--from-page M] --out OUT.pptx \
    [--report-json OUT.json] [--check-only]
```

### 10.2 报告字段

```json
{
  "deck": "DECK.pptx",
  "page": 3,
  "out": "OUT.pptx",
  "pages_before": 16,
  "pages_after": 16,
  "unchanged_others": true,
  "copied_parts": ["ppt/media/image1-2.png"]
}
```

### 10.3 退出码

- `0`：成功，回填与复核通过；
- `1`：校验失败——页码越界、来源页数不足、关系悬空或不支持、页数变化、其余页
  被改；
- `2`：用法错误或文件读取错误。
