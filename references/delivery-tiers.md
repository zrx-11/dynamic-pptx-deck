# 交付档位口径

> 本文件规定三档交付取向：什么场景选哪一档、各档允许与禁止什么、验收时
> `editability_check` 按什么规则阻断。引擎兼容性（高版本预设 / 标准安全族）
> 与交付取向（成品观感 / 可编辑性）是两个维度；本文件只约束交付取向，引擎族
> 口径见 `effects-catalog.md` 第 10 节。

## 1. 三档命名

| 档位键 | 中文名 | 默认 |
|---|---|---|
| `fidelity_first` | 成品优先档 | 是（直接交付成品时） |
| `balanced` | 效果与可编辑兼顾档 | 否 |
| `compat` | 兼容优先档 | 否 |

档位在 `deck-manifest.json` 的 `tier` 字段与各脚本 `--tier` 参数中使用，键名
逐字一致，不另起别名。

## 2. 分层原则

- 装饰层：渐变、光晕、噪点、纹理、柔化阴影、模糊、光斑、暗角可整体图像化，允许牺牲可编辑性。
- 内容层：正文、要点、数据、表格文字优先保持 `a:t` 文本节点；仅当版式无法用文本实现时才允许图片化，且必须在结构化源中登记。
- 结构层：页序、页型、内容归属必须记录在 plan/manifest 与 facts 中，与视觉层解耦；结构层永不允许图像化。

## 3. 成品优先档 `fidelity_first`（默认）

### 3.1 适用场景判定

- 交付物直接面向放映与展示：成稿即终稿，调用方在编辑器内逐元素改稿的概率低；
- 观感优先于逐元素可编辑性，装饰氛围、材质感与整页高保真度是主要诉求；
- 同时满足结构化源随稿交付、页面可按源描述重生成的硬要求（见 3.4）。

不满足 3.4 结构化源条件时，不得以成品优先档交付。

### 3.2 允许清单

- 装饰层图像化：渐变、噪点、光晕、柔化阴影、模糊、光斑、纹理用 Pillow 预渲染铺底；
- 艺术效果预烘焙：在源图阶段完成发光、模糊、阴影等效果烘焙，成稿不再挂可调参数回路；
- 图表表格局部扁平化：可对局部视觉做扁平化处理，但结构化源必须保留原始数据；
- 视觉性大字转轮廓或位图：封面主标、章节大数字等纯视觉性大字可转轮廓或位图；
- 整页高保真渲染兜底：版式确实无法用原生元素还原时，允许整页高保真渲染兜底，
  同页必须附可重生成的结构化描述（见 3.4）。

### 3.3 禁止清单

- 结构层图像化：页序、页型、内容归属不得烤进像素；
- 正文与数据图片化：除版式无法用文本实现且已在结构化源登记的情形外，正文、要点、
  数据、表格文字必须保留 `a:t` 文本节点；
- 无结构化源交付：不得只交成稿而不带 manifest、facts 与素材引用。

### 3.4 验收口径

可编辑性低不阻断；可编辑性审计按既有扣分码出报告，但低分本身不判阻断。
本档仅以下两类结构化源问题阻断：

- `SOURCE_MISSING`：无 `deck-manifest.json`，或某页在 `pages` 中无对应 `index`；
- `SOURCE_INCOMPLETE`：页面条目存在但 `content` 为空，或该页存在图片填充而
  `assets` 引用的文件未在 `assets[]` 登记。

#### 结构化源交付件

成稿同级目录必须随附：

- `deck-manifest.json`：文件名固定，结构如下——

```json
{
  "deck": "成稿文件名.pptx",
  "tier": "fidelity_first",
  "pages": [
    {"index": 1, "page_type": "cover", "content": ["主标文案", "副标文案", "期次"],
     "assets": ["assets/bg-01.png"], "notes": "装饰层为预渲染渐变"}
  ],
  "facts": "facts.md",
  "assets": [
    {"path": "assets/bg-01.png", "generator": "decor_bake/gradient",
     "params": {"colors": ["#0E3B36", "#071E1C"], "angle": 120}, "sha256": "..."}
  ]
}
```

- `facts`：事实内容清单（文案、数据、要点口径），与成稿正文一一对应；
- 素材引用：每个进入成稿的图片 / 烘焙素材在 `assets[]` 登记路径、生成器、
  生成参数与 `sha256`；同 spec 同 seed 的预渲染素材必须字节级可复现。

#### 页级重生成反向要求

- 任一页面必须能仅凭该页 manifest 条目、facts 与素材引用重建出来；
  条目里的 `content`、`assets`、`notes` 是重建依据，不得留空或只写观感描述；
- 整页高保真渲染兜底的页面，结构化描述必须写明版式分区、文案归属与装饰层配方；
- 按页局部重生成时，替换页之外的其余 slide part 必须逐字节不变（XML 哈希一致），
  被替换页的关系文件与图片资源按需复制并重映射 rId；总页数与页序不得漂移。

## 4. 效果与可编辑兼顾档 `balanced`

### 4.1 适用场景判定

- 成稿后续可能在编辑器内调整文案、配色或局部排版；
- 观感仍需达到成品水准，但装饰层预烘焙与整页扁平化让位于可编辑性；
- 既不要求兼容旧版本，也不接受大面积位图内容。

### 4.2 阻断规则

- 单页评分低于 `--threshold`（默认 70）即阻断；
- 出现 `IMAGE_PAGE`（整页图片式幻灯片）或 `TEXT_BITMAP`（文字位图化）即阻断；
- `SOURCE_INCOMPLETE` 只告警，`SOURCE_MISSING` 阻断；
- 其余扣分项（`PIC_FLATTENED` / `TABLE_SHAPE` / `CHART_SCREENSHOT` /
  `BAKED_EFFECT` / `EMPTY_CONTENT` / `BLIPFILL_HEAVY`）按审计报告复核，
  不单独阻断。

### 4.3 分层约束

装饰层图像化按单处审批：可保留局部预渲染装饰，但封面主标、正文、数据、表格
文字保持原生文本节点；不做整页高保真渲染兜底。

## 5. 兼容优先档 `compat`

### 5.1 适用场景判定

- 明确要求在旧版本 PowerPoint / 旧版 WPS 放映，或目标机版本未知且不能接受
  降级观感；
- 引擎族只下发标准 DrawingML 安全族，高版本预设不下发或仅作点缀（引擎族口径
  见 `effects-catalog.md` 第 10.3 节）。

### 5.2 阻断规则

- 阻断项与 `balanced` 相同：单页评分低于 `--threshold`（默认 70）、`IMAGE_PAGE`、
  `TEXT_BITMAP` 阻断；`SOURCE_MISSING` 阻断，`SOURCE_INCOMPLETE` 告警；
- 与 `balanced` 的差别：`BAKED_EFFECT`（艺术效果烘焙为位图）也计入阻断；
- 阈值与退出码口径与兼顾档一致。

## 6. 共同底线与排除层

- 文件结构合法、能打开、不弹修复、内容不丢、不崩；弱引擎上允许效果降级，
  但不允许因高版本写法导致文件损坏；
- 排除层任何档位都不写：内嵌视频 / mediacall、翻书页 / 页面卷曲、3D 模型位相机动画、
  空壳预设、非商业 / 个人学习许可的模板素材与照片资产；
- 三档都必须过结构体检与容器—文字配对核对；移植类与导入页效果必须在目标机
  F5 复核，结果记入验证记录。

## 7. 档位选择流程

1. 动工前先判定交付取向：直接交成品、且结构化源可随稿交付 → `fidelity_first`；
   后续要改稿 → `balanced`；明确兼容旧版本 → `compat`；未声明按 `fidelity_first`；
2. 档位写入 `deck-manifest.json` 的 `tier` 字段；脚本路由与可编辑性审计按同一
   档位键执行；
3. 成稿验收时按对应档位阻断规则跑 `editability_check`；阻断项未消解前不交付；
4. 档位切换时，装饰层配方、素材登记与可编辑性审计结论一并复核，不沿用旧档结论。
