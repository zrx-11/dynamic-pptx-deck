# 可编辑性与结构化源审计口径

> 本文件规定成稿 deck 的审计口径：哪些元素是原生可改的，哪些形态已被扁平化为位图、
> 截图或烘焙效果；各扣多少分、结构化源如何判定齐全、不同交付档位下哪些问题构成阻断。
> 审计工具为 `scripts/editability_check.py`，仅用标准库（zipfile + xml.etree）解析包内
> XML，不引入第三方渲染或 OCR。
>
> 审计目标是「AI 可重生成」：可编辑性降级为可选指标，不再单独构成阻断；真正必须齐全的
> 是结构化源（plan / manifest / facts）。分层原则、档位命名与 manifest 契约以交付档位
> 冻结稿为准。
>
> 装饰层预渲染见 `decor-bake.md`；效果路由与白名单见 `effect-routing.md`、
> `effects-catalog.md`；整页导入与适配边界见 `import-guide.md`。

## 1. 运行方式与退出码

```
python3 scripts/editability_check.py <deck.pptx> \
    [--manifest PATH] [--tier fidelity_first|balanced|compat] \
    [--report-json OUT.json] [--report-md OUT.md] [--threshold N]
python3 scripts/editability_check.py --selftest
```

- `--manifest PATH`：结构化源清单 `deck-manifest.json`；缺省时取成稿同级目录下的
  `deck-manifest.json`，仍不存在则按「无结构化源」处理。
- `--tier`：交付档位，默认 `fidelity_first`；可选 `balanced`、`compat`。档位决定哪些
  问题计入阻断，详见第 5 节。
- `--report-json OUT.json`：机器可读报告落盘；`--report-md OUT.md`：人读逐页表格落盘；
  两种输出可同时开启。
- `--threshold N`：单页达标分数线，默认 70；仅在 `balanced` / `compat` 档参与阻断判定。
- 退出码：
  - `0`：当前档位下无阻断页（warn / info 仅为复核提示，不改变退出码）；
  - `1`：存在阻断页，或结构化源缺失 / 不完整（按档位口径）；
  - `2`：包不可读、不是有效 pptx，包内没有幻灯片，或命令用法错误。

## 2. 分层原则

- **装饰层**：渐变、光晕、噪点、纹理、柔化阴影、模糊、光斑、暗角可整体图像化，允许牺牲
  可编辑性。
- **内容层**：正文、要点、数据、表格文字优先保持 `a:t` 文本节点；仅当版式无法用文本实现
  时才允许图片化，且必须在结构化源中登记。
- **结构层**：页序、页型、内容归属必须记录在 plan / manifest 与 facts 中，与视觉层解耦；
  结构层永不允许图像化。

## 3. 判定项与评分表

整包与单页均以 100 分起步，按下列权重逐项扣分，单页分数下限 0。同一页同类问题只记一条；
不同类问题按各自权重叠加。扣分码与分值固定，只增不改。

| 代码 | 扣分 | 检测方法 | 判定口径 |
|---|---|---|---|
| `IMAGE_PAGE` | 40 | 遍历本页 `p:pic` 的 `a:xfrm` 框，按框面积 / 画布面积算覆盖率；统计 `a:t` 节点数 | 最大图片覆盖率 ≥ 80% 且 `a:t` ≤ 3，判整页疑似图片式幻灯片：页面内容无法在编辑器内逐元素修改 |
| `TEXT_BITMAP` | 25 | 统计文本槽位（含文字、名称命中文本类关键词、或段落带显式 `rPr`/`pPr` 的 `p:sp`）与其中含真实 `a:t` 的数量 | 槽位 ≥ 3 但含文字槽位占比 < 0.5，或槽位 ≥ 2 而 `a:t` 为 0，判文字疑似位图化；其余可见文字可能已被烤进图片 |
| `PIC_FLATTENED` | 10 | 统计内容图片数量与最大覆盖率（背景图在 `p:bg` 内，不计入） | 仅 1–2 张图片且覆盖率 ≥ 80%、但文字节点 > 3（未触发整页图片判定），判内容被扁平化为单张图 |
| `TABLE_SHAPE` | 10 | 取有文字且带框的形状，按 x 聚列、按 y 聚行，落在网格交点上的记为单元格 | 无原生 `a:tbl`，且列 ≥ 3、行 ≥ 4、单元格 ≥ 20、短文本（≤10 字）占比 ≥ 0.65，判表格疑似用形状拼的 |
| `CHART_SCREENSHOT` | 10 | 解析本页关系中是否命中 `ppt/charts/` 图表部件；统计覆盖率 ≥ 35% 的图片 | 无原生图表部件却有占页 ≥ 35% 的图片，判图表疑似截图 |
| `BAKED_EFFECT` | 5 | 扫描 `a14:imgProps` / `a14:imgLayer` 等 a14 烘焙层节点 | 检测到烘焙位图层，判艺术效果已烘焙为位图，参数不可再编辑 |
| `EMPTY_CONTENT` | 3 | 统计形状、文字、图片、表格、图表数量 | 无任何形状、文字或图片，页面近乎空白 |
| `BLIPFILL_HEAVY` | 1 | 统计 `p:sp` 下 `spPr/blipFill` 数量 | 形状图片填充 ≥ 3 个；填充本身可编辑，仅提示核对用途，不构成降级问题 |

可编辑效果节点（`a:blur`、`a:glow`、`a:prstShdw` 挂在 `a:effectLst` 下）只计入统计，
不扣分——这些参数在编辑器内仍可调。`useBgFill="1"` 的透明窗形状同样只统计，不扣分。

## 4. 结构化源齐全性

结构化源文件名为 `deck-manifest.json`，放在成稿同级目录。审计按以下规则逐页判定，不
自创规则：

| 源码 | 触发条件 | 含义 |
|---|---|---|
| `SOURCE_MISSING` | 无 `deck-manifest.json`，或某页在 `pages[]` 中找不到对应 `index` | 页面的页型、文案归属、素材登记完全缺失，AI 无法据此重生成该页 |
| `SOURCE_INCOMPLETE` | 页面条目存在但 `content` 为空；或该页存在图片填充，而 `assets` 引用的文件未在顶层 `assets[]` 登记 | 条目不完整：缺文案归属，或图片素材没有来源 / 参数登记，重生成时无法复刻 |

判定细节：

- `content`：页面条目内的文案 / 要点 / 数据归属列表；为空记不完整。
- 图片填充判定：本页存在 `p:pic`、形状 `blipFill` 或背景 `blipFill` 之一，即视为有图片
  填充；此时条目 `assets` 引用的每个文件路径必须出现在顶层 `assets[]` 登记中，否则记
  不完整。
- 结构化源不参与可编辑性扣分；它单独成码，按第 5 节档位口径决定告警还是阻断。

## 5. 分档阻断口径

阻断规则按档位真分档。同一问题在不同档位下的级别（`block` / `warn`）不同：

| 问题 / 条件 | `fidelity_first`（成品优先，默认） | `balanced`（效果与可编辑兼顾） | `compat`（兼容优先） |
|---|---|---|---|
| `SOURCE_MISSING` | 阻断 | 阻断 | 阻断 |
| `SOURCE_INCOMPLETE` | 阻断 | 仅告警 | 仅告警 |
| 单页评分 < `--threshold` | 不阻断（低分允许） | 阻断 | 阻断 |
| `IMAGE_PAGE` | 不阻断（装饰 / 成品图允许） | 阻断 | 阻断 |
| `TEXT_BITMAP` | 不阻断 | 阻断 | 阻断 |
| `BAKED_EFFECT` | 仅告警 | 仅告警 | 阻断 |
| `PIC_FLATTENED` / `TABLE_SHAPE` / `CHART_SCREENSHOT` / `EMPTY_CONTENT` / `BLIPFILL_HEAVY` | 仅告警 | 仅告警 | 仅告警 |

- `fidelity_first`：可编辑性低不阻断；只有结构化源问题构成阻断。成品优先交付时，装饰层
  与成品图可以整体图像化，只要源清单登记齐全。
- `balanced`：低分页、整页图片页、文字转图即阻断；结构化源不完整只告警，缺失才阻断。
- `compat`：同 `balanced`，并把已烘焙为位图、参数不可再调的效果计入阻断。

## 6. 整包 verdict 判定线

整包 `verdict` 取以下三档之一（描述性判定，不直接等于阻断结论；是否阻断以第 5 节与
`blocking_pages` 为准）：

| 档位 | 判定线 | 含义 |
|---|---|---|
| `editable` | 无任何问题记录，且结构化源齐全 | 成稿由原生元素构成，源清单完整 |
| `mixed` | 存在告警或阻断问题，但不满足 `image_based` | 部分元素需复核或重建；按问题清单逐条处理 |
| `image_based` | 任一页面触发 `IMAGE_PAGE` | 成稿以位图为主；成品优先档可接受，兼顾 / 兼容档需回到源稿按原生路线重建 |

- 整包分数为各页分数的算术平均（四舍五入）。
- `blocking_pages` 列出当前档位下所有阻断页的页码。
- 判定线只依据包内 XML 结构、几何统计与 manifest 登记；脚本不打开幻灯片做视觉比对。

## 7. 常见「看起来能改、其实不能改」的形态与识别特征

### 7.1 整页截图 / 整页图片式幻灯片

- **识别特征**：一张图片铺满画布（覆盖率 ≥ 80%），全页 `a:t` ≤ 3；形状清单里几乎只剩
  这一张 `p:pic`。
- **为什么不能改**：标题、正文、配色、层级全部固化在像素里，点击图片只能整体挪动或替换，
  无法改字、换色、调层级。成品优先档允许以成品图交付，但必须在结构化源中登记该页内容
  归属。

### 7.2 文字被烤进图片

- **识别特征**：页面上能看到文字，但文本槽位大多为空，`a:t` 节点数远少于页面应有的
  文字量；或页面配图占据主要面积而无对应文本节点。
- **为什么不能改**：可见文字是图片像素，编辑器里选不中、改不了；复制出来的只是空文本框
  外壳。

### 7.3 内容扁平化为单张图

- **识别特征**：整页只有 1–2 张全幅图片，其余元素可选中性很差；文字可能仍以少量独立
  文本框叠在图上。
- **为什么不能改**：图内的图形、图标、分区不可拆分；叠加文本可改，图内内容不可改。

### 7.4 用形状拼出来的「表格」

- **识别特征**：没有原生 `a:tbl`，但页面呈多列多行对齐的短文本网格：表头一行短标签，
  下面多行同列对齐的单元格文字。
- **可改程度**：若每个格子是独立文本框，文字仍可逐格修改；风险在于行 / 列底色常被做成整
  排图片，或调整列宽时格子不会像原生表格那样自动重排。

### 7.5 图表截图

- **识别特征**：没有引用 `c:chart` 图表部件，却有一张占页 ≥ 35% 的大图，位置和尺寸对应
  常规图表区。
- **为什么不能改**：系列、类目、数值都固化在图里；不能换数据、不能改配色、不能切换图表
  类型。

### 7.6 艺术效果烘焙为位图

- **识别特征**：图片上挂 `a14:imgProps` / `a14:imgLayer` 烘焙层；效果看起来是模糊、发光、
  阴影的成品，参数面板里调不动。
- **为什么不能改**：烘焙把效果算进了像素，成稿上只剩结果图，失去参数回路。兼容优先档下
  这类问题计入阻断。

### 7.7 不要误判的两类：背景图与透明窗

- **背景图**：图片填充挂在 `p:bg/bgPr/blipFill` 上，属于页面底色层，不计入内容图片覆盖率，
  不触发整页图片判定。
- **`useBgFill` 透明窗**：形状本身透明、透出背景，是可编辑的叠层结构，只统计不扣分。
- 区分要点：内容图片是 `p:spTree` 下的 `p:pic` 或形状图片填充；背景图在 `p:bg` 内。

## 8. 分类修复建议

| 问题类别 | 修复做法（按优先级） |
|---|---|
| 整页图片式（`IMAGE_PAGE`） | 1. 回到源稿，用 `p:bg` 承载背景底色，标题、正文、分区全部改用原生形状与文本框重建；2. 复杂插画作为独立素材放在独立图层，文案与结构保持原生，不要把整页合成一张图贴回；成品优先档保留贴图时，须在 manifest 登记该页文案归属与素材来源 |
| 文字位图化（`TEXT_BITMAP`） | 1. 逐处核对空槽位，把图片里的文字还原为独立文本框；2. 必须保留图片文字时，在结构化源与备注里记录图片来源与文案，避免后续误以为可在成稿上改字 |
| 单图扁平化（`PIC_FLATTENED`） | 1. 把图内可拆分的图形、图标、分区还原为原生形状；2. 保留为贴图时，至少保证文案为独立文本框，图内元素不承担可编辑结构 |
| 形状拼表格（`TABLE_SHAPE`） | 1. 优先改用原生 `a:tbl`，让表头、单元格、行列随数据重排；2. 保留形状方案时，每格必须是独立文本框，行 / 列底色用形状填充，不要把整行整列烤成图片 |
| 图表截图（`CHART_SCREENSHOT`） | 1. 保留或重建 `c:chart` 原生图表，数据系列与类目挂图表部件；2. 只能贴图时，按系列 / 类目逐元素重建可编辑图形，并在结构化源中记录数据来源与口径 |
| 烘焙效果（`BAKED_EFFECT`） | 1. 在源图阶段完成预烘焙，把所用参数（模糊半径、发光颜色、阴影方向与距离）记录进配方；2. 成稿上不再挂 a14 烘焙层，需要可调的效果改用 `effectLst` 下的可编辑节点 |
| 结构化源缺失（`SOURCE_MISSING`） | 1. 按 plan / facts 补建 `deck-manifest.json`，逐页登记 `index`、页型、`content` 与素材引用；2. 结构层（页序、页型、内容归属）必须先补齐，再谈视觉层是否可图像化 |
| 结构化源不完整（`SOURCE_INCOMPLETE`） | 1. 补全页面 `content` 文案 / 要点 / 数据归属；2. 把页面图片填充引用的素材登记进顶层 `assets[]`，记录生成方式与参数 |
| 空白页（`EMPTY_CONTENT`） | 1. 补齐内容或删除该页；2. 确认是否为导出时漏写内容，而非排版留白 |

## 9. 脚本不覆盖什么

- **不做 OCR**：无法识别图片像素里是否含有文字，也读不出图内文案；`TEXT_BITMAP` 只能
  依据「槽位数量 vs `a:t` 节点数」的差距做推断，可能漏掉已烤进图片但槽位清空的情形，也
  可能把纯装饰空壳误计入槽位（口径已按名称与段落格式收窄，仍需人工复核）。
- **不判断图片内容含义**：无法区分一张大图是插画、图标还是图表截图；`CHART_SCREENSHOT`
  只按「无图表部件 + 大图占比 ≥ 35%」给提示。
- **不校验视觉效果**：不渲染幻灯片，不检查配色、字号阶梯、对齐美观度，也不判断动画时序
  是否合理。
- **不解析嵌入对象与 OLE**：忽略 OLE 对象、嵌入 Office 文档等特殊部件的可编辑性。
- **不做版式版权与素材来源核查**：可编辑性只描述结构状态，不替代许可与来源审查。
- **网格启发式有限**：表格拼装判定基于行列聚类与短文本占比，卡片墙、时间轴等重复卡片
  布局可能逼近阈值；命中后需人工确认是表格还是卡片排版。
- **manifest 内容不做事实核对**：脚本只检查条目是否存在、`content` 是否为空、素材路径
  是否登记；不校验文案与 facts 是否一致，也不校验图片与登记参数是否相符。

## 10. 输出结构（JSON / MD）

### 10.1 顶层字段

```
{
  "deck": { "file": "<文件名>", "tier": "<档位>", "score": <整包分数>,
            "verdict": "editable | mixed | image_based",
            "blocking_pages": [<阻断页码>] },
  "pages": [ <逐页报告> ],
  "summary": { "by_code": { "<代码>": <次数> }, "threshold": <达标线>, "pages": <页数> }
}
```

### 10.2 逐页字段

```
{
  "index": <页码，从 1 起>,
  "score": <本页分数>,
  "verdict": "ok | warn | block",
  "findings": [
    { "code": "<代码>", "severity": "block | warn", "region": "<位置>",
      "count": <次数>, "reason": "<可读说明>" }
  ],
  "source": { "complete": <bool>,
              "missing": ["SOURCE_MISSING | SOURCE_INCOMPLETE", ...] },
  "stats": {
    "shapes": <形状总数>, "sp": <自动形状>, "pic": <图片>,
    "graphic_frame": <图表框>, "group": <组合>,
    "text_shapes": <含文字形状>, "text_slots": <文本槽位>, "text_nodes": <a:t 数>,
    "native_tables": <原生表格>, "native_charts": <原生图表>,
    "shape_blipfills": <形状图片填充>, "pic_blips": <图片 blipFill>,
    "bg_blipfill": <是否背景图填充>, "use_bg_fill": <useBgFill 形状数>,
    "editable_effects": <可编辑效果节点>, "baked_effects": <烘焙层节点>,
    "max_pic_coverage": <最大图片覆盖率>,
    "pic_ratios": [ { "id", "name", "coverage" } ],
    "grid": { "cols", "rows", "cells", "short_cells", "short_ratio" },
    "has_image_fill": <是否存在图片填充>
  }
}
```

### 10.3 MD 报告

MD 报告先给档位、总体判定、整包分数、达标线与阻断页，再出一张逐页表（页码、分数、判定、
图片数、原生表格、原生图表、结构化源状态、问题清单），最后按页列出各问题的级别、代码与
说明。
